1. UNIFIED HARNESS CLI
================================================================================

Primary entry point: python -m harness.cli <command>

status
  Purpose: Health-check all services, models, market data, and strategy imports.
  Usage:   python -m harness.cli status

dashboard
  Purpose: Unified dashboard showing health, Alpaca account, open positions,
           recent trades, market-data freshness, RL model status, and regime.
  Usage:   python -m harness.cli dashboard
           python -m harness.cli dashboard --trade-limit 20
           python -m harness.cli dashboard --health-timeout 2 --max-age-hours 25

data
  Purpose: Refresh the parquet market-data cache (1d, 1h, or both).
  Usage:   python -m harness.cli data
           python -m harness.cli data --interval 1h --force-full
           python -m harness.cli data --tickers AAPL MSFT

data_collection
  Purpose: Collect sentiment + risk snapshots for every ticker in the union
           universe.  Scheduled at 08:00/11:00/14:00/17:00 ET.
  Usage:   python -m harness.cli data_collection

signal_generation (alias: run)
  Purpose: Collect signals from all 4 strategies, reconcile, allocate capital,
           and execute paper trades.  Hourly market-hours job.
  Usage:   python -m harness.cli signal_generation
           python -m harness.cli signal_generation --dry-run
           python -m harness.cli signal_generation --ticker AAPL
           python -m harness.cli run --mode confidence_weighted

report
  Purpose: Print unified P&L, positions, and strategy comparison.
  Usage:   python -m harness.cli report

positions
  Purpose: Show all open positions across every strategy DB.
  Usage:   python -m harness.cli positions

backtest
  Purpose: Run per-strategy backtests and compare reconciliation modes.
  Usage:   python -m harness.cli backtest
           python -m harness.cli backtest --days 365 --strategy mr

schedule
  Purpose: Register Windows Task Scheduler jobs for the pipeline.
  Usage:   python -m harness.cli schedule

train
  Purpose: Retrain RL models (single ticker or all configured RL tickers).
  Usage:   python -m harness.cli train
           python -m harness.cli train --ticker AAPL --timesteps 100000

retrain-check
  Purpose: Check RL models for rolling Sharpe degradation and optionally
           auto-retrain degraded models.
  Usage:   python -m harness.cli retrain-check
           python -m harness.cli retrain-check --auto-retrain --retrain-timesteps 50000
           python -m harness.cli retrain-check --min-sharpe 0.6 --ticker AAPL

logs
  Purpose: Tail recent log files from all services.
  Usage:   python -m harness.cli logs
           python -m harness.cli logs --lines 100

comprehensive TICKERS...
  Purpose: Auth-protected deep-dive analysis on tickers.
  Usage:   python -m harness.cli comprehensive AAPL MSFT TSLA

5. API SERVICES (FastAPI)
================================================================================

These services expose HTTP endpoints used by other components.  They are not
run from a CLI directly; launch them with uvicorn (or via `python -m app.main
from the backend directory).

--------------------------------------------------------------------------------
5.1 sentiment_analysis
--------------------------------------------------------------------------------

Launch:  cd sentiment_analysis\backend
         sentiment_analysis\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

Endpoints:
  GET  /                 - Root / health info
  GET  /api/health        - Service health check
  POST /api/analyze        - Analyze sentiment for a ticker (used by risk + strategies)
  POST /api/alerts         - Check sentiment alerts for a list of tickers
  GET  /api/cache          - Sentiment cache statistics
  DELETE /api/cache/{ticker} - Invalidate cache for a ticker
  GET  /api/sources        - List available news sources
  GET  /api/history/{ticker} - Historical sentiment snapshots (limit=90)
  POST /api/comprehensive  - Deep-dive comprehensive analysis

--------------------------------------------------------------------------------
5.2 risk_calculator
--------------------------------------------------------------------------------

Launch:  cd risk_calculator
         risk_calculator\venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8100

Endpoints:
  GET  /api/health         - Service health check (also checks sentiment upstream)
  POST /api/risk            - Full risk report for a ticker (used by strategies)
  POST /api/risk/portfolio  - Portfolio-level risk report (used by harness)
  GET  /api/history/{ticker} - Historical risk snapshots (limit=90)

NOTES
================================================================================

- Strategy-level paper trading CLIs (`paper`, `positions`) are intentionally
  disabled; all production trading is routed through the harness.
- Many scripts use venv-specific Python executes.  If a venv is missing, the
  harness CLI generally falls back to the current `python` interpreter.
- For API services, the harness CLI will auto-start them when needed (see
  `_ensure_services_up` in harness/cli.py).
